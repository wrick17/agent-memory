### Local full-transcript replay (#22), 2026-11-04

`agent-memory replay` serves full local Claude Code and Codex transcripts to a browser on the recording machine. It loads the shared player above, byte for byte. Nothing it reads is uploaded or stored in a hosted system.

- Commands: `--list` prints local sessions, newest first. `--session ID` opens one session, `--port N` picks the port (default 0, a random free port), and `--help` prints usage. Bad arguments exit 2; an unknown session or a failed start exits 1.
- Sources: `projects/<project>/<session>.jsonl` under the Claude Code home and `sessions/YYYY/MM/DD/rollout-*-<uuid>.jsonl` under the Codex home. Listed files must be regular files owned by the current user, and symlinks are not followed. Session ids are validated. Each read opens with `O_NOFOLLOW` and checks `fstat`.
- Events: owner and assistant text comes from the hook's `extract()`, so thinking, system, meta, sidechain and injected context stay out. A Claude command record, one that opens with `<command-name>` or `<local-command-stdout>`, stays out whole. Owner text after injected context in the same record is kept. Tool calls and results are kept for both formats. A lone string argument shows as its bare value only when redaction would leave its JSON form unchanged; otherwise the key stays, so key-based redaction applies. Every label and detail is redacted. Claude text blocks between two tool blocks form one event and are redacted together, so a secret split across blocks is caught. If a secret is split across a tool block, the record's text shows once, before its tool events. Each tool input and output is cut at 8 KB after redaction (`truncated: "true"`).
- Server: binds 127.0.0.1 only. A random 32-byte token is the first URL path segment and is compared in constant time. Host must be exactly `127.0.0.1:<port>`, and Origin, when sent, must be the same origin. These checks run before routing or file access. Only GET and HEAD are allowed. Responses set a self-only CSP with no inline script or style, plus `no-store`, `nosniff`, `no-referrer` and frame denial. There are no redirects. Errors carry no paths or transcript text.

### Capture project tagging, 2026-11-12

Source on branch `feat/capture-project-tagging`; not merged, deployed or reviewed yet.

- Client (`processSession`, so live capture and `backfill` both): `placeOf` sends the optional batch fields `project` (`github:<owner>/<repo>`, from `git rev-parse --show-toplevel` and the origin remote through `facts.mjs` `repoKey`) and `workspace` (a `capture.workspaces` name). `repo {remote, path}` and routing are unchanged.
- Worker: `/v1/ingest` accepts both fields as optional. Old clients send neither and are unaffected. After the digests are stored, `ProfileStore.linkProject` writes `session part_of project` through the `knowledge` write as actor `index`, with activity and undo and the request id `capture-project:<profile>:<session node>:<key>`. It creates the project node only when no active node has that key (case-insensitive match), never rewrites an existing node, and adds a new work project's name to the `me` guard terms. The command is planned again after the last account call and right before the synchronous write, so a project the owner creates meanwhile, under any key casing, is linked rather than overwritten or duplicated. A created project's account registration is kept as a `capture-register:<node id>` row in `profile_meta` and retried on every later batch until it succeeds; it never holds back the digests. A link failure never fails the capture. Fixture and malformed keys are skipped. The workspace is stored as session `attrs.workspace`.
- Learning: `learningFor` already scoped lessons and decisions to the session's `part_of` project and linked them with `relates_to`. A session with no project now uses its workspace as the scope.
- Read: session rows add `project_key` (the project node's key) and `workspace`. `project` is still the node id.
- No schema migration and no rewrite of existing records. Sessions captured before this change stay unlinked until a separate, staged backfill.
- Rollout: Worker first, then the client. An older Worker refuses the new fields with HTTP 400. The client keeps those batches spooled or pending and retries them, so capture stalls but loses nothing until the Worker is upgraded.
- Limits: the workspace exists only as a session attribute, not as a node. Maintenance writes no journals, so journals have no project link from this change. MCP tools are unchanged.
- Owner format (PR #156): GitHub owners may contain `_`, as Enterprise Managed User logins such as `owner_shortcode` do. An owner starts and ends with a letter or digit and has at most 39 characters. The client `repoKey`, the Worker's capture `project` check and the repo-facts `REPO_KEY` all accept it, so these checkouts get a project key and repo facts. Before, they got `project_key: null`. A session captured without a key is linked on its next batch. Verification: `local/facts.test.mjs` cases for an underscore owner over SSH and HTTPS and for a rejected trailing `_`; `npm run test:local` 379/379, `npm run typecheck` passed, `vitest test/capture.test.ts` 21/21.
- Active project match (2026-11-13): capture links a session only to an `active` project node. When several active nodes match the key case-insensitively, the exact-case key wins, then the earliest. Before, it took the earliest non-`moved` node of any status, so an older retired fixture under another casing (the work profile's `github:Sequoia-Engineering/kernel-eureka-frontend` acceptance node) took real sessions. When no active node matches, capture creates the project under its lowercase key; the case-sensitive `nodes_key` index allows that beside a node under another casing. When an inactive node holds the exact key, capture links nothing rather than rewrite it. The owner `forget` action moves a node into `archive`, so lookups never see a forgotten node. A work upload's project `ensure` also prefers an active node, then the exact-case key, then the earliest; it still reuses an inactive match when no active one exists. It fails on the old lookup.
