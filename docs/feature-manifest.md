# Agent Memory feature manifest

This is the commitment index. [Confirmed requirements](../research/00-requirements.md#confirmed-decisions) govern product intent; [architecture v3.2](architecture.md#decisions-at-a-glance) describes the approved design and phase checks. The owner approved the final implementation plan on 2026-10-28 with "Let's build it", then authorized all necessary non-deleting changes without further approval prompts. Implementation may proceed through the planned phases; runtime claims still require their implementation checks.

**Status baseline:** No feature below is fully verified. Parts of several are implemented with local checks and selected live evidence; each row says what exists and what is still unproven. On 2026-10-28 phase 1 was implemented in part for AM-01, AM-02, AM-03, AM-05, AM-06 and AM-07, with local tests and selected live evidence; their rows say what exists and what is still unproven ([phase 1 implementation](phase-1-implementation.md)). Phase 2's capture vertical (AM-09, AM-10) followed with local checks only ([phase 2 implementation](phase-2-implementation.md)). The phase-1 Worker is deployed for owner testing; gates remain open. Evidence links distinguish passing local and provider checks from design sources and pending live gates. Phase numbers refer to the [proposed plan](architecture.md#22-implementation-plan); I means the [import vertical](architecture.md#import-vertical-bothq-and-curated-markdown-memory), F the [final backup stage](architecture.md#final-stage-backup-and-restore), and C final rehearsal and cutover. **Owner priority, 2026-10-29:** "Too priority should be the memory system, mcp and ingesting current memory in bothq and md files." The core memory store and MCP come first; after the capture vertical's review fixes, the next vertical is a lossless, resumable, idempotent one-way copy of BothQ and the curated Markdown memory into the hosted profiles for review, ahead of capture extras, advanced graph, dashboard and corpus. BothQ stays the only live system; the copy is refreshed and reconciled before cutover ([migration](architecture.md#16-migration-and-cutover)). **Owner timing decisions, 2026-10-29** ([plan](architecture.md#22-implementation-plan); superseded timing in the [plan as approved on 2026-10-28](https://github.com/wrick17/agent-memory/blob/6ab2380ee3b3182bad3d6a8a5fe9bc130b5ccaa9/docs/architecture.md#22-implementation-plan)): backup and restore are built and tested in the final backup stage, after every other feature and before BothQ shutdown, and nothing of them is built or rehearsed earlier; physical cross-machine parity checks move to the final combined rehearsal. Contracts, gates and feature IDs are unchanged, and no backup gate is passed. The [v3.1 closure review](review-sol-v31-2026-10-28.md#six-closure-verdicts) closed export ties, publish-before-commit recovery and confinement in the design, alongside previously closed F2, F5, F6, F9 and F10. Parent Sol's bounded source check on 2026-10-28 closed the three remaining A/B/C cases against [v3.2's corrections](architecture.md#changes-since-v31), SHA-256 `08f7dd0f9e3873c96b40ad3c4a6e85538b1a82490b89388b70a673c8b584972a`: the R2 generation ledger survives account rollback; persisted digest parts and a tiling manifest gate acknowledgement; work wipe redacts undo payloads and replaces affected exports. ## Maintenance

1. Before a product behavior, interface or decision change, read this manifest and the linked authoritative sections for affected features.
2. In the same change, update every affected entry, phase and status; link the specific implementation and relevant check evidence. Add an ID for a new commitment and retain existing IDs.
3. Record intentional decision changes with their reason, date and superseded decision or source. Preserve a link to the prior record instead of silently rewriting history. Record known deferrals and unresolved design findings explicitly.
4. Mark a feature implemented only when its promised behavior exists. Mark it verified only when the relevant check actually passed, with a link to the result and its scope. Design documents and reviews are not implementation or runtime verification.
